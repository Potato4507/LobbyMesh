# Decisions
Voice quality (2026-10-28): use bounded browser-native scalar RTT/jitter/loss from the isolated media owner, retaining no candidates or raw reports. Keep optional diagnostics separate from media liveness: failed/slow stats show unavailable, while host integrity and capture teardown stay strict. One owned main sample per second with expiry/phase generation prevents stale UI. Show network RTT explicitly rather than claiming physical audio latency.
Voice interruption (2026-10-28): preserve the browser's existing five-second disconnect grace, expose reconnecting and mute immediately. Require fresh PTT after recovery. Treat only the trusted bounded MEDIA_NOT_CONNECTED talking race as nonfatal; retain hard teardown for timeout/invalid/error paths. Do not add an authenticated heartbeat while native RPC setup remains serialized: queued control traffic is not reliable evidence of media failure. Same-host process-kill observations and injected transient browser events have distinct evidence labels.

ADR 018 (2026-10-28): implement call output attenuation/mute in an owned WebAudio gain graph, independently of capture/PTT/transport. Keep Chromium's decoder-driving element silent; measure RMS after user gain before hardware/OS output, exporting only a bounded scalar/null. Verify actual quarter-gain and mute waveforms in separate desktop processes; do not infer VAD, perceived volume, physical output or latency from the meter. Call-local settings reset and updates coalesce under bounded IPC.

ADR 017 (2026-10-28): expose voice only through explicit main-window consent/call/answer and focused hold-to-talk, resolving targets from approved contacts. Use independently expiring main/media talk leases and a mute watchdog; renewal cannot rearm after expiry without a new press. Native focus acceptance requires actual focus transfer, not a no-op blur request. Keep capture-on/muted-transmission visible and preserve unknown capture/transmission plus failed cleanup through network shutdown. No overlay/global-game voice activation yet.

ADR 016 (2026-10-28): centralize call/media ownership in VoiceCalls. Incoming authenticated offers never capture; only local answer allocates media. Synchronous control-ended notifications close the sandboxed owner; abortable media work and owner identity checks prevent late results mutating another call. Only observed local WebRTC connection state promotes past negotiation timeout, with a nonrenewing one-hour active bound. Preserve unknown capture and deny new calls on unconfirmed teardown. Native proof must carry real SDP through app authentication, not bypass control with a browser-only loopback.

ADR 015 (2026-10-28): keep capture/PeerConnection in a dedicated sandboxed media renderer with no generic app bridge. A trusted main owner scopes the microphone gate to its local main frame and active consent, validates bounded replies and destroys the renderer on cancellation/failure. Pool at most four nonpersistent sessions because Electron retains partition objects for the process lifetime. Check decoded audio in both directions; native host testing exposed and fixed an answerer transceiver that had never sent audio.

ADR 014 (2026-10-28): implement the browser WebRTC/Opus primitive separately from production permission/IPC integration. Explicit local consent and trusted permission precede audio-only capture; start muted, require connected state plus an explicit talking gate, and stop tracks returned after cancellation/deadline. Keep default production permission denial. Validate real synthetic decoded audio/PTT release in a sandboxed Electron test with zero-volume sinks; transport packet counters alone do not establish decoded audio or real microphone acceptance.

ADR 013 (2026-10-28): stage voice by implementing bounded authenticated control before capture. Keep production disabled until an isolated media owner and explicit OS/local permission are implemented; never simulate working audio controls. Reuse pinned direct Noise transactions for signaling and keep SDP/ICE local/ephemeral. Local hangup/cancel/denial wins over late remote completions. Control negotiation is separate from media identity, active audio and group membership; those acceptance gates remain unfinished.

ADR 012 (2026-10-28): use signed short-lived app contact codes for explicit local approvals, independent of network/session discovery. Preview is offline, approval pins app identity before guarded atomic persistence, and both participants retain independent default-deny policies. This is not manual server/network configuration or proof of human/Roblox identity/age. Keep invitations out of public DHT records, cap ephemeral tickets, deny overlay/foreign grant IPC, retain newer deny tokens and drain owned saves on close. No age/safety or release acceptance inferred from pairing tests.

ADR 011 (2026-10-28): integrate overlay widgets with the same main-process status/session/messaging services through a narrowly authorized second renderer. Use standard Electron Windows window/input APIs; no Roblox injection or fullscreen promise. Reuse atomic preferences with strict backward-compatible optional overlay migration, default disabled and passive on reopen. A global shortcut is optional convenience with visible registration failure and desktop fallback. Voice controls await real audio implementation.

ADR 010 (2026-10-28): Windows player logs are a local, read-only, self-asserted session source. Match only explicit timestamped engine lifecycle markers, require all scope identifiers and connection confirmation, bound reads and reject stale/ambiguous files. Keep detection permission coupled to the explicit session-consent control; networking/contact permission remains independent. No HTTP identity/roster enrichment, addresses/account IDs retained, or manual seed fallback. Native fixture proof does not establish real Roblox compatibility. See windows-log-detection.md for freshness/exit limits.

ADR 001: Node 24 LTS, TypeScript strict, pnpm 11.25.0, Electron 45.1.0 and React 19.3.1. Node built-in test runner via tsx is the equivalent deterministic test framework. Electron renderer is sandboxed with no Node, denied permissions, local CSP, no navigation, and one argument-validated status IPC restricted to its main frame. No network or audio is enabled by the scaffold.

ADR 002: Use Node OpenSSL Ed25519, never custom crypto. Initial fallback storage is a 0700 directory and 0600 exclusive-created key file on POSIX; Windows needs an OS-protected adapter before release. Unsupported future key formats fail closed rather than being overwritten.

ADR 003: Pin HyperDHT 6.35.0. Its upstream README and installed source confirm lookup/announce/unannounce/createServer/listen/destroy APIs. Use stock public bootstrap defaults only for entrypoint discovery. Transport identity is a separately persisted seed/keypair; `transport:<hex>` hints must never pass as authenticated app PeerIds. No app session IDs appear in public topic. Current backend rejects incoming streams until M07 installs an authenticated handler. Public UDP smoke timed out; external availability unresolved.

ADR 004: App overlay foundation uses 256-bit XOR IDs, k=20 retained contacts/bucket and bounded signed record store. Full buckets retain established entries; eviction/liveness checks and iterative lookup remain M08. LocalOverlay deliberately does not implement the preliminary ApplicationDHT interface yet: its signed record schema is versioned RecordV1 and network join/RPC remain absent. A fake announcement is unit evidence only.

ADR 005 (2026-10-27): Keep public HyperDHT transport/discovery separate from application RPC routing/store. Bind app Ed25519 identity to the pinned library's 64-byte Noise handshake hash and both transport keys with domain-separated signatures; no custom encryption. One framed request/response per stream bounds state and avoids premature multiplexing. HyperDHT streams use streamx `write`/`drain`, not Node write callbacks (caught by real-process test). Referrals are hints until authenticated and app-ID pinned. Original handoff-replaced prompts retained under docs/handoff-originals. Repository .gitattributes enforces LF to avoid Windows checkout-only lint failures.

ADR 006: Bound iterative lookups by alpha=3, 32 node queries, 64 candidates and 3 seconds. Report budget/deadline/failed peers instead of treating them as an empty network. Native transactions temporarily serialize (64 queued maximum) because real same-host parallel setup stalls were observed; this is an explicit throughput tradeoff pending transport investigation, not a claim that alpha=3 native requests run concurrently. Retry simultaneous join transport failures at most twice with jitter; never retry forged identity as successful authentication. Graph-scale fixtures and real local-process fixtures are separate evidence.

ADR 007: Import pinned HyperDHT statically and externalize it from Electron/CommonJS bundles. createRequire(import.meta.url) fails after CJS bundling; the verified fix retains installed native addon resolution. CJS bundle import and native Electron factory import are separate tests. Loading the factory creates no network activity.

ADR 008: Windows desktop credentials use Electron 45 async safeStorage in the trusted main process. Availability/decryption failure blocks network startup with a distinct credential error and no automatic retry or plaintext fallback. Migration preserves app and transport identity, verifies durable ciphertext before replacing legacy plaintext with a nonsecret marker, and refuses ambiguous conflicts. Keep explicit Node plaintext loaders for synthetic development harnesses; they cannot open/reset protected state. Support other OS providers only after native verification. Windows DPAPI protection does not isolate other apps running as the same OS user.

ADR 009: Record repair performs bounded target-specific resolution and uses authenticated lookup results for replica placement even when established live bucket incumbents prevent active admission. Previously authenticated replacement-cache contacts remain bounded lookup/referral candidates. Keep replica writes inside the existing overall repair budget. Validate recovery with the production maintenance controller, including periodic shared discovery; a repair-only fixture with one bridge is a different scenario and its failure must remain visible. Seeded in-process streams verify app protocol behavior, not native encryption or internet convergence.
