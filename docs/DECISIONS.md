# Decisions

ADR 001: Node 24 LTS, TypeScript strict, pnpm 11.25.0, Electron 45.1.0 and React 19.3.1. Node built-in test runner via tsx is the equivalent deterministic test framework. Electron renderer is sandboxed with no Node, denied permissions, local CSP, no navigation, and one argument-validated status IPC restricted to its main frame. No network or audio is enabled by the scaffold.

ADR 002: Use Node OpenSSL Ed25519, never custom crypto. Initial fallback storage is a 0700 directory and 0600 exclusive-created key file on POSIX; Windows needs an OS-protected adapter before release. Unsupported future key formats fail closed rather than being overwritten.

ADR 003: Pin HyperDHT 6.35.0. Its upstream README and installed source confirm lookup/announce/unannounce/createServer/listen/destroy APIs. Use stock public bootstrap defaults only for entrypoint discovery. Transport identity is a separately persisted seed/keypair; `transport:<hex>` hints must never pass as authenticated app PeerIds. No app session IDs appear in public topic. Current backend rejects incoming streams until M07 installs an authenticated handler. Public UDP smoke timed out; external availability unresolved.

ADR 004: App overlay foundation uses 256-bit XOR IDs, k=20 retained contacts/bucket and bounded signed record store. Full buckets retain established entries; eviction/liveness checks and iterative lookup remain M08. LocalOverlay deliberately does not implement the preliminary ApplicationDHT interface yet: its signed record schema is versioned RecordV1 and network join/RPC remain absent. A fake announcement is unit evidence only.

ADR 005 (2026-10-27): Keep public HyperDHT transport/discovery separate from application RPC routing/store. Bind app Ed25519 identity to the pinned library's 64-byte Noise handshake hash and both transport keys with domain-separated signatures; no custom encryption. One framed request/response per stream bounds state and avoids premature multiplexing. HyperDHT streams use streamx `write`/`drain`, not Node write callbacks (caught by real-process test). Referrals are hints until authenticated and app-ID pinned. Original handoff-replaced prompts retained under docs/handoff-originals. Repository .gitattributes enforces LF to avoid Windows checkout-only lint failures.

ADR 006: Bound iterative lookups by alpha=3, 32 node queries, 64 candidates and 3 seconds. Report budget/deadline/failed peers instead of treating them as an empty network. Native transactions temporarily serialize (64 queued maximum) because real same-host parallel setup stalls were observed; this is an explicit throughput tradeoff pending transport investigation, not a claim that alpha=3 native requests run concurrently. Retry simultaneous join transport failures at most twice with jitter; never retry forged identity as successful authentication. Graph-scale fixtures and real local-process fixtures are separate evidence.

ADR 007: Import pinned HyperDHT statically and externalize it from Electron/CommonJS bundles. createRequire(import.meta.url) fails after CJS bundling; the verified fix retains installed native addon resolution. CJS bundle import and native Electron factory import are separate tests. Loading the factory creates no network activity.

ADR 008: Windows desktop credentials use Electron 45 async safeStorage in the trusted main process. Availability/decryption failure blocks network startup with a distinct credential error and no automatic retry or plaintext fallback. Migration preserves app and transport identity, verifies durable ciphertext before replacing legacy plaintext with a nonsecret marker, and refuses ambiguous conflicts. Keep explicit Node plaintext loaders for synthetic development harnesses; they cannot open/reset protected state. Support other OS providers only after native verification. Windows DPAPI protection does not isolate other apps running as the same OS user.

ADR 009: Record repair performs bounded target-specific resolution and uses authenticated lookup results for replica placement even when established live bucket incumbents prevent active admission. Previously authenticated replacement-cache contacts remain bounded lookup/referral candidates. Keep replica writes inside the existing overall repair budget. Validate recovery with the production maintenance controller, including periodic shared discovery; a repair-only fixture with one bridge is a different scenario and its failure must remain visible. Seeded in-process streams verify app protocol behavior, not native encryption or internet convergence.
