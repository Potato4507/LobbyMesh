# Versioned implementation contracts

All implemented packages are v1. Preliminary ApplicationDHT/SignedRecord interfaces remain legacy scaffolding; NetworkOverlay uses the existing validated RecordV1 schema, not the legacy unsigned byte contract.

Overlay RPC v1: `companion/app-overlay/rpc/v1`, mandatory overlay-rpc capability. One transaction per HyperDHT Noise stream. Mutual Ed25519 app signatures bind canonical hellos, both transport keys and the unique 64-byte Noise handshake hash using identity-binding/v1 domain. PeerId is SHA256(SPKI), never a Roblox identity. 24KiB length-prefixed JSON frames, four received frames maximum, default 5-second transaction deadline, cancellation and streamx drain backpressure. No protocol handler executes before authentication. Errors are generic on wire. HyperDHTBackend defaults to reject-all unless an inbound handler is explicitly injected; caps 32 total application streams, 10-second stream lifetime, forced stream cleanup on close. These limits apply after native Noise connection establishment, not to all internal library UDP/handshake allocations.

NetworkOverlay v1: explicit start, single-use leave/abort, authenticated routing admission, join deduplication (32 in flight), at most 20 referrals per join, referral identity pinning on reconnect. FIND_NODE, FIND_VALUE (two records/page) and PUT with validation on both boundaries. Exact signed duplicate replication is idempotent; lower/conflicting sequence rejected by RecordStore. Default three closest replicas report observed successes/failures. Reads currently query up to 20 direct neighbors, at most 32 pages/peer and 64 distinct authors; quota failure is explicit. Per-request deadline exists; overall iterative deadlines and anti-entropy are next. Local block callback applies to caller and record author; persistent block/settings UI remains pending. No claim of verified Roblox session or universal reachability.

M08 supersedes direct-neighbor traversal above: iterativeLookup uses alpha=3, 32 peer queries, 64 candidates, 3-second overall deadline, identity deduplication and XOR ordering. NetworkOverlay serializes native transactions with queue cap 64 due locally observed overlapping setup stalls; queued canceled work checks cancellation before opening a socket. Network lookup exposes partial records and routing diagnostics; get rejects empty incomplete/failed lookups. A budget-limited search is never proof of global absence. At most 32 two-record pages/peer and 64 result authors. Transient joins retry twice with jitter; forged/protocol-incompatible responses do not qualify as transient errors. leave aborts requests and drains queued work. Anti-entropy and periodic discovery not yet implemented.

Runtime supersedes the pending maintenance note above: createOverlayRuntime composes persisted app/transport identities, backend, public discovery, NetworkOverlay and lifecycle-owned maintenance. Start is deduplicated; startup failure closes resources; stop is idempotent and aborts live work. Real probe results are computed from authenticated RPC, never a wire boolean. Maintenance defaults to a non-overlapping 30s interval, repeats discovery/refresh/announcement and runs bounded record reconciliation. No autonomous OS service. Network per-request default is 1500ms; overall lookup 3000ms. Reconciliation scans at most 16 records/cycle, up to three nearest replicas, 2s overall budget, preserves original signatures/TTL. Saturation/slow links can prevent convergence before expiry; status exposes budget rather than claiming completion. Empty single-node results describe local knowledge only.

Session matching v1: canonical JSON array domain + decimal universe/place strings + bounded JobId, SHA256 epoch-scoped key (60s epoch), query current and previous epochs. 60s signed ads contain only domain/version, joined/left, consent assertion, chosen display name, transport key and claimed evidence provenance; raw session IDs are omitted. Signed tombstones replace ads on leave, consent withdrawal or scope change; disconnected replicas expire naturally, no guaranteed remote erasure. All records validated for key, signature and current expiry on consumption. Malformed/blocked ads ignored; incomplete routing raises SESSION_LOOKUP_INCOMPLETE. Remote externally-verified assertions are output as self-asserted unless a future independent verifier exists; app-key-only is always explicit. SessionCoordinator defaults to no consent, takes only injected providers, coalesces events, handles stale initial reads, refreshes every 20s and clears stale results on withdrawal/failure/stop. No legitimate production provider is implemented by this module.

Direct control/text v1: authenticated app RPC dispatches explicit companion/direct/v1 messages only to an injected direct handler (otherwise disabled). DirectMessenger independently requires local peer authorization, default deny, before send/receive/hello/ping. NetworkOverlay.directRequest pins expected app identity and shares its bounded native queue. Hello negotiates text-v1; heartbeat validates pong. Text envelopes bind from/to app IDs, random 128-bit ID, random sender epoch, monotonic per-process sequence, timestamp and <=4096 UTF8 bytes. Reject >30s future or >=120s old. Matching IDs with different canonical content conflict; exact repeats acknowledge without redelivery. Three bounded attempts, 2s default attempt deadline, cancellation and finite backoff; ACK means accepted into memory, not read. Memory dedupe/retention/rate quotas and restart/purge limitations are detailed in local-direct-text.md. Persistent policy and desktop wiring are next; these primitives alone do not establish human consent or child-safety compliance.

Preferences v1: fixed version/fields, network false/sessionConsent false/voice off initially, chosen display name, <=256 allowed and <=1024 blocked app IDs. Unknown fields/types/future versions rejected; block wins over allow and unblock never implies allow. PreferenceStore owns an exclusive lock until close, serializes updates, writes synced temporary files then renames, updates visible persisted snapshot only on success. In-memory block/revoke takes effect immediately and stays denied on storage failure. Authorization false while closing. Copies on snapshot. Lock ownership token checked before unlink; stale locks fail closed and require explicit recovery rather than automatic deletion. Windows ACL and crash durability remain unverified; this settings store does not protect identity secrets or enable audio/network by itself.

Desktop network lifecycle: trusted main-frame boolean opt-in IPC only; permission is saved before a new instance starts. Opt-out cancels immediately even on persistence failure, which is surfaced because old startup permission may remain on disk. Default off; saved opt-in restarts automatically. Generic preferences IPC cannot set networkEnabled. Status exposes phase/intent/known-peer count/discovery/retry/error without transport keys or server IDs. Startup 15s, shutdown 3s, three attempts with exponential backoff/jitter; runtime force-closes native server after 1s cleanup grace. Generation guards reject stale completion; unconfirmed cleanup stays error. Factory must honor cancellation. Power events stop/resume only when enabled. All IPC guarded by window/main-frame identity and cap 16 in-flight operations. Direct permissions remain a separate persistent local policy; networking itself never authorizes messaging.

Identity: loadOrCreateIdentity(directory) persists PKCS8 Ed25519 with exclusive creation and rejects corrupted/future versions. Concurrent creation fails closed; callers must retry after the creator completes. Identity closure exposes signing but not private export. resetIdentity removes local credentials; remote revocation is not implemented. POSIX fallback permissions tested. Windows credential protection and migration are incomplete.

RecordStore: key-bound canonical JSON arrays, domain app-overlay/v1, SPKI public key, SHA256 PeerId, Ed25519 signatures, safe integer sequence, 120-second TTL maximum, 8KiB serialized input and 1024 author/key slots. Replay high-water marks bounded for process lifetime. Capacity exhaustion rejects new slots (availability tradeoff). This is a local security primitive, not a complete app DHT. Caller must bound incoming frames BEFORE JSON decoding; records take untrusted decoded objects only.

Session: MockSessionProvider is test-only, accepts only mock provenance; copies on publish/read. No production session API or manual server-ID entry.

Roster: consumes previously authenticated opted-in app participants; does not prove consent or Roblox account identity from an untrusted boolean. Callers must validate ads and establish consent before join. Rejects invalid identifiers, control characters and quota overflow; names need not be unique. Exports only whitelisted app data and enforces block on rejoin. In-memory block persistence and moderation remain unfinished.

Public-discovery/v1: fixed SHA256 topic, transport-key hints with no connection address export, at most 256 candidates/query, lookup minimum 1s and announce minimum 30s, query deadline 10s. Injected query destroy MUST terminate pending async iteration. Listening and graceful unannouncement currently depend on backend completion; standalone smoke bounds the entire lifecycle at 15s. Backend instances are single-use after stop; allocate a fresh HyperDHTBackend to reconnect. Periodic republishing/backoff and persistent key OS protection remain integration work. Memory fake supports restart. Native keys are intentionally distinct from app identity; binding required in M07.

Entrypoint-search/v1: max 4 parallel probes, 64 unique keys, overall deadline (default 3s), AbortSignal forwarded to probes. Probe is a trusted adapter responsible for real cryptographic verification; an untrusted wire boolean must never populate authenticated directly. Injected probes and iterators must release resources on cancellation; timeout bounds caller waiting but cannot force arbitrary injected code to terminate. Discovery hints alone are insufficient. No-reachable-candidate is never proof that no overlay exists.

LocalOverlay v1: start publishes entrypoint through injected discovery; failure cleans discovery. put/get only while running; leave clears ephemeral routing/store. RPC, join and peer authentication absent. RoutingTable accepts already authenticated app contacts only (not raw public hints); caller must validate key-to-PeerId binding in M07. All contact output is copied, connection hints discarded.
