# Versioned implementation contracts
Voice interruption: browser disconnected clears talking and disables audio tracks immediately, exposes local reconnecting, and starts the existing5000ms failure grace. Connected recovery never rearms transmission. Main accepts mute during reconnecting; new talking requires locally connected media. The exact MEDIA_NOT_CONNECTED reply is nonfatal for a talking race; other errors/invalid replies/timeouts retain owner teardown. Capture remains on until cleanup confirms otherwise. No remote state assertion can promote media connectivity.

Call output v1 (local only): finite volume0–1 and boolean incoming mute, strict current-call-bound main-window action/media command. No wire protocol or microphone/PTT change. Gain->analyser->hardware graph exports only normalized post-gain RMS0–1/null via status; unavailable is never zero. Per-call settings reset, one output write at a time; UI coalesces slider intent and main mute watchdog closes unconfirmed output. See evidence/call-output-controls.md.

Native independent-client harness uses the production desktop/network factory with an optional trusted main-only local bootstrap override. It does not expose bootstrap/endpoint fields to UI, alter production defaults or use public bootstrap during the test. Two source-built Electron main processes isolate profiles/OS-protected identities and exchange real signed pairing/Noise SDP/synthetic media; restart retains identity/revocation but never voice permission. See evidence/independent-voice-clients.md.

Desktop voice IPC: main window only, exact action/consent/peer/call IDs; no SDP/endpoints. Connection-local consent defaults off. Focus required for grants/call/answer/talk. PTT start vs renewal separated; UI250ms/main600ms/media750ms leases, release and cancel bypass ordinary quota, mute ACK watchdog200ms closes host if unconfirmed. Voice/status remains redacted. Ordinary overlay/foreign voice actions deny. Unknown capture/transmission persists through failed teardown/disconnect; network shutdown propagates the failure while closing other services. See evidence/desktop-voice-controls.md.

VoiceCalls links authenticated control events to a per-call media owner. Incoming offer retains ephemeral SDP and rings without capture; explicit local answer required. Local connected-media observation alone promotes beyond negotiation30s to fixed active lifetime1h (not extended by polling). Every control ending synchronously closes the owned host; abort/owner checks prevent stale completion affecting a new call. Unknown/failed teardown retains ownership and reports capture=null/disabled. Current adapter uses complete ICE SDP; separate trickle ICE fails explicitly. Production service is wired with scoped OS-status-aware media factory but consent defaults off with explicit main-window UI activation. See evidence/authenticated-call-media.md.

Desktop media host: one sandboxed media-only renderer per instance, pooled nonpersistent sessions capped at four simultaneous hosts, default-denied audio-only permission tied to trusted consent/availability and exact owned main frame URL. Narrow command/reply preload; main pins sender frame and validates bounded result/error schemas. Default12s host command/start deadline, pending4; close destroys contents/rejects work/removes listeners/resets permission handlers. Only this media renderer may receive SDP; ordinary desktop/overlay IPC remains excluded. Voice activation is limited to the main-window controls. See evidence/isolated-media-host.md.

Browser AudioPeer primitive: single-use, explicit consent and trusted permission callback before audio-only capture. Local tracks muted initially; explicit talking gate, Opus-only one-audio-transceiver, complete-ICE SDP with bounded audio/Opus/SHA256 fingerprint validation, five-second operation budgets, close/late-result cleanup. Missing received energy is null; observed Chromium energy zero cannot prove silence. Dedicated media renderer/VoiceCalls now own the primitive; no actual microphone grant acceptance yet. See evidence/browser-audio.md.

Voice control v1: strict `type=voice`, `protocol=companion/media/v1` direct envelopes for offer/answer/ice/hangup. App identity/transport pinned by existing Noise RPC, explicit local contact and voice consent plus trusted media availability required. One call, explicit answer, 30s negotiation, 2s default send, eight outstanding, 48 ICE/direction, 64 local events, bounded replay/call/rate history. Abort and deny clear sensitive pending data; direct authenticated signaling alone does not establish DTLS/audio identity. SDP/ICE remain opaque here, never persisted/published as DHT records or exposed through ordinary desktop/overlay IPC. VoiceCalls supplies the media bridge; consent defaults off and explicit main-window actions activate it. See evidence/voice-signaling.md and authenticated-call-media.md.

Contact invitation v1: LM1 + canonical base64url JSON <=4096 bytes, exact keys and domain-separated Ed25519 array signature. App key, PeerId, transport key, chosen name, nonce, issued/expiry bound; TTL <=120s, <=5s future skew. Preview is offline/no grant; <=8 single-use opaque tickets and one active approval. Only trusted desktop main frame may approve with explicit consent=true. Before save, authenticated RPC pins the invitation app ID/Noise endpoint and validates an overlay reply. Both local policies must approve independently for text. No platform/account/age proof. Close/cancel/policy changes invalidate pending work; save guards and ordered denial tokens prevent stale grant/unblock from undoing newer deny actions. Pending save drains on network shutdown. If cancellation races atomic rename, compensating revoke precedes completion; failure is surfaced. Signed invite itself is transferable/reusable until expiry. See evidence/contact-pairing.md.

Native RPC diagnostics retain 32 recent attempts plus 16 failures and aggregate outcomes with bounded enum/timing fields only; no identifiers/content/raw errors. App-ID-pinned calls may retry one timeout/closed connection in hello/proof before request transmission, with 25–74ms backoff and block/cancellation recheck. Caller/lookup deadlines remain unchanged. Never retry identity/protocol rejection, remote application error or post-transmission failure here. Liveness counts final logical failures; snapshots count physical attempts, retaining recovered failures. Queued cancellation is labeled aborted even during teardown. See evidence/native-rpc-reliability.md.

Current source/catch-up supersedes the original 256KiB tail notes: production process gate requires log creation and modification >= player start, avoiding previous-player late flushes. Read sequentially from offset zero, <=4MiB/poll, retaining bounded partial/parser state; publish scanning/null until caught up to observed size. Never skip unobserved middle events or publish a historical head join as current. Diagnose --follow bounds waiting to 30s; it does not guarantee a session. Latest live result is waiting/no selected session. See evidence/windows-log-catchup.md.

Production Windows detection now additionally requires supported same-desktop-session RobloxPlayerBeta activity metadata: one running lifetime, file/event evidence after its start; exit/multiple/failed queries clear current evidence. Queries are bounded (1.5s/16KiB/4 results) and cached five seconds including failure. No privileged escalation or memory/command-line reads. Redacted status reason distinguishes process/log ambiguity and query/read failure. Standalone provider fixtures without activity retain 120s freshness. Live probe currently rejects multiple eligible logs; no successful real Roblox detection claimed. See evidence/windows-player-lifecycle.md.

Overlay preferences extend v1 with enabled=false, four work-area corners, opacity 0.5–1 and 1–3 unique ordered widgets (network/session/chat). Legacy seven-field settings get default overlay values; unknown fields and explicit malformed overlay objects still fail closed. Snapshot and patch copy nested widget arrays. Separate non-injected Window defaults to click-through/non-focusable, saved opt-in resumes passively; interaction mode is process-local. Allowlisted overlay main-frame IPC may use status/mode/authorized messaging only. Lifecycle closes the overlay and its shortcut; full input/fullscreen acceptance remains unverified.

Desktop session integration supersedes the pending note below: production network factory receives the same local provider and live name/consent projection, starts DesktopSessions after network startup, and stops it alongside transport shutdown. Matching remains independent from contact authorization. Status projects state plus count excluding self/blocked; incomplete lookup is visible as error rather than global absence. Name updates republish on the next coordinator reconciliation. Remote shutdown copies may persist until signed TTL expiry.

WindowsLogSessionProvider implements SessionProvider with `windows-log` / `self-asserted` provenance. See evidence/windows-log-detection.md for supported paths/markers and bounded freshness behavior. Desktop status adds a redacted detection object (state/source/verification); no session IDs or log contents are sent to the renderer. Session consent starts/stops polling, default off; failed opt-out persistence stops current monitoring, though saved consent may remain on disk for restart. A later unrelated preference save cannot re-enable it. Desktop matching integration remains pending.

All implemented packages are v1. Preliminary ApplicationDHT/SignedRecord interfaces remain legacy scaffolding; NetworkOverlay uses the existing validated RecordV1 schema, not the legacy unsigned byte contract.

Overlay RPC v1: `companion/app-overlay/rpc/v1`, mandatory overlay-rpc capability. One transaction per HyperDHT Noise stream. Mutual Ed25519 app signatures bind canonical hellos, both transport keys and the unique 64-byte Noise handshake hash using identity-binding/v1 domain. PeerId is SHA256(SPKI), never a Roblox identity. 24KiB length-prefixed JSON frames, four received frames maximum, default 5-second transaction deadline, cancellation and streamx drain backpressure. No protocol handler executes before authentication. Errors are generic on wire. HyperDHTBackend defaults to reject-all unless an inbound handler is explicitly injected; caps 32 total application streams, 10-second stream lifetime, forced stream cleanup on close. These limits apply after native Noise connection establishment, not to all internal library UDP/handshake allocations.

NetworkOverlay v1: explicit start, single-use leave/abort, authenticated routing admission, join deduplication (32 in flight), at most 20 referrals per join, referral identity pinning on reconnect. FIND_NODE, FIND_VALUE (two records/page) and PUT with validation on both boundaries. Exact signed duplicate replication is idempotent; lower/conflicting sequence rejected by RecordStore. Default three closest replicas report observed successes/failures. Reads currently query up to 20 direct neighbors, at most 32 pages/peer and 64 distinct authors; quota failure is explicit. Per-request deadline exists; overall iterative deadlines and anti-entropy are next. Local block callback applies to caller and record author; persistent block/settings UI remains pending. No claim of verified Roblox session or universal reachability.

M08 supersedes direct-neighbor traversal above: iterativeLookup uses alpha=3, 32 peer queries, 64 candidates, 3-second overall deadline, identity deduplication and XOR ordering. NetworkOverlay serializes native transactions with queue cap 64 due locally observed overlapping setup stalls; queued canceled work checks cancellation before opening a socket. Network lookup exposes partial records and routing diagnostics; get rejects empty incomplete/failed lookups. A budget-limited search is never proof of global absence. At most 32 two-record pages/peer and 64 result authors. Transient joins retry twice with jitter; forged/protocol-incompatible responses do not qualify as transient errors. leave aborts requests and drains queued work. Anti-entropy and periodic discovery not yet implemented.

Runtime supersedes the pending maintenance note above: createOverlayRuntime composes persisted app/transport identities, backend, public discovery, NetworkOverlay and lifecycle-owned maintenance. Start is deduplicated; startup failure closes resources; stop is idempotent and aborts live work. Real probe results are computed from authenticated RPC, never a wire boolean. Maintenance defaults to a non-overlapping 30s interval, repeats discovery/refresh/announcement and runs bounded record reconciliation. No autonomous OS service. Network per-request default is 1500ms; overall lookup 3000ms. Reconciliation scans at most 16 records/cycle, up to three nearest replicas, 2s overall budget, preserves original signatures/TTL. Saturation/slow links can prevent convergence before expiry; status exposes budget rather than claiming completion. Empty single-node results describe local knowledge only.

Session matching v1: canonical JSON array domain + decimal universe/place strings + bounded JobId, SHA256 epoch-scoped key (60s epoch), query current and previous epochs. 60s signed ads contain only domain/version, joined/left, consent assertion, chosen display name, transport key and claimed evidence provenance; raw session IDs are omitted. Signed tombstones replace ads on leave, consent withdrawal or scope change; disconnected replicas expire naturally, no guaranteed remote erasure. All records validated for key, signature and current expiry on consumption. Malformed/blocked ads ignored; incomplete routing raises SESSION_LOOKUP_INCOMPLETE. Remote externally-verified assertions are output as self-asserted unless a future independent verifier exists; app-key-only is always explicit. SessionCoordinator defaults to no consent, takes only injected providers, coalesces events, handles stale initial reads, refreshes every 20s and clears stale results on withdrawal/failure/stop. The Windows log provider is implemented separately with local self-asserted provenance; actual game compatibility remains unverified.

Direct control/text v1: authenticated app RPC dispatches explicit companion/direct/v1 messages only to an injected direct handler (otherwise disabled). DirectMessenger independently requires local peer authorization, default deny, before send/receive/hello/ping. NetworkOverlay.directRequest pins expected app identity and shares its bounded native queue. Hello negotiates text-v1; heartbeat validates pong. Text envelopes bind from/to app IDs, random 128-bit ID, random sender epoch, monotonic per-process sequence, timestamp and <=4096 UTF8 bytes. Reject >30s future or >=120s old. Matching IDs with different canonical content conflict; exact repeats acknowledge without redelivery. Three bounded attempts, 2s default attempt deadline, cancellation and finite backoff; ACK means accepted into memory, not read. Memory dedupe/retention/rate quotas and restart/purge limitations are detailed in local-direct-text.md. Persistent policy and desktop wiring are next; these primitives alone do not establish human consent or child-safety compliance.

Preferences v1: fixed version/fields, network false/sessionConsent false/voice off initially, chosen display name, <=256 allowed and <=1024 blocked app IDs. Unknown fields/types/future versions rejected; block wins over allow and unblock never implies allow. PreferenceStore owns an exclusive lock until close, serializes updates, writes synced temporary files then renames, updates visible persisted snapshot only on success. In-memory block/revoke takes effect immediately and stays denied on storage failure. Authorization false while closing. Copies on snapshot. Lock ownership token checked before unlink; stale locks fail closed and require explicit recovery rather than automatic deletion. Windows ACL and crash durability remain unverified; this settings store does not protect identity secrets or enable audio/network by itself.

Desktop network lifecycle: trusted main-frame boolean opt-in IPC only; permission is saved before a new instance starts. Opt-out cancels immediately even on persistence failure, which is surfaced because old startup permission may remain on disk. Default off; saved opt-in restarts automatically. Generic preferences IPC cannot set networkEnabled. Status exposes phase/intent/known-peer count/discovery/retry/error without transport keys or server IDs. Startup 15s, shutdown 3s, three attempts with exponential backoff/jitter; runtime force-closes native server after 1s cleanup grace. Generation guards reject stale completion; unconfirmed cleanup stays error. Factory must honor cancellation. Power events stop/resume only when enabled. All IPC guarded by window/main-frame identity and cap 16 in-flight operations. Direct permissions remain a separate persistent local policy; networking itself never authorizes messaging.

Desktop messaging: only an online lifecycle instance can expose its messaging service. Summary contains approved app IDs and whether a previously authenticated transport is known (discovered is not guaranteed current reachability). History for one approved contact is capped at 50 entries; projection includes actual contact context, local UI ID, nullable wire ID and delivery state. Strict send IPC accepts only peerId/text; all transport resolution stays in main. Contact grant is absent. Prioritize status and disconnect even when 16 ordinary IPC slots are busy. Revocation cancels pending sends; unknown/blocked IDs cannot fetch/send/clear history. Explicit clear and disconnect purge in-memory state; no disk/offline history. UI text is escaped, no remote HTML or automatic links, and late responses cannot replace another selected conversation. Full bounds/evidence in desktop-messaging.md.

Identity: loadOrCreateIdentity(directory, protection?) and loadTransportKeys(directory, protection?) accept the main-process SecretProtection adapter. Windows desktop supplies async Electron safeStorage, with no plaintext fallback; development callers without the adapter retain explicit plaintext storage. Version-1 legacy keys are sealed, flushed and verified before atomic retirement to nonsecret version-2 markers. Existing public identities stay unchanged. Conflicting/corrupt/missing marked ciphertext fails closed; concurrent fresh creators fail exclusive creation and retry reads the winner. Protected formats are identity-os-v1.bin and transport-os-v1.bin; provider-requested resealing preserves identity. Identity closure exposes signing but not private export. Legacy resetIdentity refuses protected storage; protected reset and remote revocation are not implemented. See evidence/windows-credentials.md for scope and limitations.

Routing recovery: k=20 active contacts plus at most k authenticated replacement candidates per bucket. Full buckets retain live incumbents; removal after two failed RPCs promotes the newest eligible cached contact. Replacements are previously authenticated hints, not fresh liveness proof or Sybil-resistant human identities. Refresh probes four globally least-recently active contacts within a two-second budget before iterative lookup. Successful authentication advances recency; fresh inbound activity prevents an older in-flight failure from counting. User/lifecycle cancellation does not count as failure. Canceled callers leave the bounded native queue promptly; their queued tasks retain quota slots until drained and cannot open sockets after cancellation. Blocked contacts are filtered from referrals/desktop contact views and replacement promotion.

Synchronization fairness: scan at most 16 signed records per invocation, with a default 2000ms budget (validated synchronizationMs override 1–10000). A budget stop advances past attempted records; completing a store sweep rotates the order of the three nearest replica candidates. This prevents a stable slow first record/closest replica from starving later records/reachable replicas in a stable fixture. User/lifecycle abort preserves the scan position. Dynamic churn/expiry can change numeric scan positions; subsequent sweeps revisit live records. No global convergence bound without usable transport and stable-enough retained records is promised.

Target-aware repair: each attempted record first resolves its target through iterative authenticated lookup, bounded to min(500ms, half the configured synchronization budget), within the overall cycle budget. Replica selection combines active contacts with freshly authenticated lookup results and chooses three nearest eligible peers. PUT likewise uses its lookup results even when live full buckets retained those peers only in replacement caches. Referral/lookup candidates may include bounded previously authenticated replacements; this does not promote them to active incumbents or establish fresh liveness. RoutingTable.stats reports active/replacement/bucket counts without exposing mutable state. The simulator drives production maintenance with a synthetic shared bootstrap and synthetic stream metadata; results cannot establish native Noise/NAT behavior.

RecordStore: key-bound canonical JSON arrays, domain app-overlay/v1, SPKI public key, SHA256 PeerId, Ed25519 signatures, safe integer sequence, 120-second TTL maximum, 8KiB serialized input and 1024 author/key slots. Replay high-water marks bounded for process lifetime. Capacity exhaustion rejects new slots (availability tradeoff). This is a local security primitive, not a complete app DHT. Caller must bound incoming frames BEFORE JSON decoding; records take untrusted decoded objects only.

Session: MockSessionProvider is test-only, accepts only mock provenance; copies on publish/read. The separate Windows provider reads local logs; there is no official production session API or manual server-ID entry.

Roster: consumes previously authenticated opted-in app participants; does not prove consent or Roblox account identity from an untrusted boolean. Callers must validate ads and establish consent before join. Rejects invalid identifiers, control characters and quota overflow; names need not be unique. Exports only whitelisted app data and enforces block on rejoin. In-memory block persistence and moderation remain unfinished.

Public-discovery/v1: fixed SHA256 topic, transport-key hints with no connection address export, at most 256 candidates/query, lookup minimum 1s and announce minimum 30s, query deadline 10s. Injected query destroy MUST terminate pending async iteration. Listening and graceful unannouncement currently depend on backend completion; standalone smoke bounds the entire lifecycle at 15s. Backend instances are single-use after stop; allocate a fresh HyperDHTBackend to reconnect. Periodic republishing/backoff and persistent key OS protection remain integration work. Memory fake supports restart. Native keys are intentionally distinct from app identity; binding required in M07.

Entrypoint-search/v1: max 4 parallel probes, 64 unique keys, overall deadline (default 3s), AbortSignal forwarded to probes. Probe is a trusted adapter responsible for real cryptographic verification; an untrusted wire boolean must never populate authenticated directly. Injected probes and iterators must release resources on cancellation; timeout bounds caller waiting but cannot force arbitrary injected code to terminate. Discovery hints alone are insufficient. No-reachable-candidate is never proof that no overlay exists.

LocalOverlay v1: start publishes entrypoint through injected discovery; failure cleans discovery. put/get only while running; leave clears ephemeral routing/store. RPC, join and peer authentication absent. RoutingTable accepts already authenticated app contacts only (not raw public hints); caller must validate key-to-PeerId binding in M07. All contact output is copied, connection hints discarded.
