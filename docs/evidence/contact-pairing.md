# Explicit contact onboarding — 2026-10-28

/goal: let fresh profiles approve known app contacts without editing settings files, manually configuring the network, or granting permission from a session claim.

/steps: LM1 contact codes contain a versioned domain-separated Ed25519 signature over app public key/ID, transport key, chosen name, random nonce and <=120s lifetime. Strict <=4096-byte canonical base64url decoding, exact fields, app-key derivation, TTL/skew and signature checks. No session IDs, account/age claims, addresses or private keys. Preview stays local and grants nothing; <=8 opaque tickets, consumed once, with one active approval. Approval has a five-second abortable authentication budget and pins the expected app identity over the existing Noise RPC before permission can be saved. Existing block policy applies before preview/connection/commit; disclosure/fingerprint confirmation is explicit in UI. Each side must approve independently; sharing a code alone grants nothing. Codes remain reusable until expiry; tickets are single-use, not the entire invitation.

Production network factory composes DesktopPairing with the same identity, authenticated overlay and messaging policy. Successful approval retains a short-lived authenticated transport hint for immediate messaging even when routing buckets are full. Main-window-only IPC separates create, preview, consent=true approval and cancellation; no generic allow action added. Overlay/foreign windows are denied. UI shows the full app fingerprint and self-chosen name as unverified/app-key-only, expires codes, preserves policy limits and links empty conversations to Preferences. It never requests microphone access or disables safety protections.

Persistence/reliability: guarded atomic writes recheck approval before writing and before rename. If canceled during commit, immediate denial and a compensating revoke complete before returning failure; rollback failure has a specific user-visible recovery message. Versioned in-memory denial tokens prevent an older grant/unblock completion clearing a newer revoke/block. Revoke now denies unknown peers immediately too, covering a queued fresh grant. Pairing shutdown aborts authentication and drains its owned save before releasing policy storage. Crash/power-loss/OS ACL and failed-compensation durability remain unverified; do not imply absolute remote erasure.

/proof: Windows Node 24.22.1 / pnpm 11.25.0 / Electron 45.1.0. Full 101/101, typecheck/lint (105 files), build/native desktop smoke passed. Eight new cases cover signed field/expiry/size tampering, no-preview grant, persisted approval/reopen/single ticket use, blocked/failed/canceled/expired/late auth, quotas, revoke/commit compensation, block/unblock ordering and save-draining shutdown. Real local two-process runtime now pairs via signed codes instead of directly seeding both permissions; valid signature pointing to a different app endpoint fails PEER_ID_MISMATCH with no grant. One-sided approval remains undeliverable; after both approvals actual encrypted text/ACK and revocation work. These processes use generated app identities/synthetic rooms on one host.

Native Electron fixture uses synthetic contact authentication with real temporary preferences: create/review, no authentication before approval, checkbox gating, rejected consent=false request, escaped malicious chosen name, persisted approval and removal, plus overlay denial. New lobbymesh-pairing-test.png visually reviewed and labeled synthetic; this is no claim of a real person's consent/identity. Existing sandbox/IPC/network/overlay/credential tests still pass.

Limits: contact codes are public transferable app metadata; they do not prove human identity/age, Roblox membership or safe behavior. Trusted-channel fingerprint checking is a user action, not independently verified by software. Formal age/contact/safety acceptance and real cross-network onboarding remain incomplete; no production release claim. Safe local explicit approval is implemented, not universal social-safety compliance. Direct paths may fail under NAT and disclose network addresses as already explained. Transport reuse, audio, positive real Roblox lifecycle and installer/distribution gates remain.
