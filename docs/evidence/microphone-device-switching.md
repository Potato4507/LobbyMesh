# Explicit microphone selection — 2026-10-29

Connected calls now offer an explicit Refresh microphones / Use microphone flow in the main window. Enumeration never runs on startup or on receipt of an incoming offer. Listing and switching require a focused, trusted main frame and the exact current call ID; switch requests require true consent. The overlay has no access to either operation. Device selection is per call, never persisted or sent to another peer.

Raw browser device IDs stay in the sandboxed media owner. At most 31 hardware choices plus System default cross IPC as random 128-bit tokens and sanitized labels of at most 80 characters. Refresh, devicechange and owner teardown invalidate hardware tokens. Enumeration is bounded to 128 records and 1000 ms; a timed-out native job remains single-flight until it settles. Unavailable enumeration returns an explicit bounded fallback. Expired choices are rejected without destroying healthy media, and do not resume PTT. Labels are local UI data, not diagnostics.

Switching clears main-process PTT intent and its lease, confirms mute, stops both old raw and processed tracks, detaches the old input context, then requests audio-only capture with the chosen exact device constraint. It replaces the existing audio sender track in the same RTP call, preserving gain. The new raw and processed tracks start disabled. A fresh PTT press is required; a held renewal cannot reactivate capture transmission. Concurrent switches, gain changes and talk activation are denied during replacement. Capture/replacement failure closes the media owner; late capture after cancellation/timeout is stopped independently. Device interruption still ends capture rather than silently switching or resuming.
