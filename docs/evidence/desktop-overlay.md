# Modular desktop overlay — 2026-10-28

/goal: a functional customizable Windows overlay integrated with the same desktop services.

/steps: separate sandboxed, context-isolated, non-injected always-on-top window. Saved enable/opacity/corner/ordered widget list share the existing exclusive, atomic PreferenceStore. Existing seven-field v1 preference files migrate in memory with overlay off by default; current schema validates all fields and copies nested arrays. Connection, redacted session presence and approved chat widgets render actual service state. Chat reuses the desktop message UI and permission checks; no fake audio controls. Widgets may be hidden/re-added to change order; at least one stays enabled.

Input defaults to non-focusable and click-through. Explicit desktop interaction button or Ctrl+Shift+Space toggles keyboard/mouse interaction; Back to game returns to passive mode. Shortcut registration failure is visible with the desktop button as fallback. Primary-display work-area corners and bounded size avoid offscreen layouts, including negative-origin/small displays; display changes reposition. Disabling/closing tears down the window, listeners and only its owned shortcut. Saved enable resumes passive, never steals focus at startup. Overlay IPC is limited to status, overlay mode and existing authorized messaging; network controls, settings and contact changes are rejected. Foreign windows stay rejected.

/proof: Windows Node 24.22.1 / pnpm 11.25.0 / Electron 45.1.0. `pnpm typecheck`, `pnpm lint` (94 files), `pnpm test` (82/82), `pnpm build` passed. `pnpm test:desktop` passed with temporary profiles and synthetic traffic. Native checks cover window focusability/always-on-top flags, no renderer Node, privilege rejection, interaction toggle, real renderer send/ACK via the existing synthetic direct transport, widget removal, disable/destroy, saved layout and passive restart. Native credential independent-process reopen remains passing. Screenshot lobbymesh-overlay-test.png is visibly marked synthetic and was reviewed. Hidden compositor capture initially retained an older frame; the harness now briefly shows without focus to capture current painted state. During development a test-file name collision temporarily replaced tests/overlay.test.ts; original tests were restored unchanged, new cases moved to desktop-overlay.test.ts, and full 82-test coverage rerun.

Official API references inspected: [BrowserWindow](https://www.electronjs.org/docs/latest/api/browser-window), [globalShortcut](https://www.electronjs.org/docs/latest/api/global-shortcut), plus installed Electron 45 declarations. No third-party overlay/injection dependency introduced.

Limits: no actual Roblox/borderless/exclusive-fullscreen game, physical mouse click-through, real global keypress or OS focus handoff was exercised. Native flags and renderer actions are evidence of implementation, not physical game acceptance. Exclusive fullscreen/secure desktops may cover the window. Primary display only; freeform dragging/resizing, per-game profiles and configurable shortcut are future work. Overlay chat still requires existing authorized contacts; fresh-profile onboarding, voice, NAT acceptance and packaging remain unfinished. No release claim.
