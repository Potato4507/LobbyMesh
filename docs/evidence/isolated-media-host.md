# Isolated media host — 2026-10-28

VERIFIED_UNIT / VERIFIED_INTEGRATION / PARTIAL. `DesktopMediaHost` owns one dedicated sandboxed BrowserWindow for a call, with its own nonpersistent Session and a narrow media-only preload. No production desktop/overlay IPC invokes it yet. Host creation and audio capture remain separate: status can load an idle host, but only explicit trusted offer/answer consent enables a capture request. Microphone grant also requires a separate trusted `microphoneAllowed` callback, which defaults to deny.

Permission check and request handlers independently require current consent, owned webContents, the exact local media.html URL, main frame, `media` permission and exactly audio. Video, display capture, subframes, other pages and other windows deny. The regular desktop/overlay session remains unchanged/default-denied. The host cannot override Windows microphone privacy settings; real OS permission UI/device acceptance is still missing.

Media preload permits only validated command subscription/replies and redacted sandbox diagnostics. Main accepts replies only from its owned main frame at the expected URL, matches random command IDs, validates exact bounded result schemas and exports only safe error codes. A foreign renderer using the genuine media preload cannot mark another host ready. No eval, arbitrary URL or generic IPC bridge. SDP is confined to the dedicated media frame and trusted main-process owner, never ordinary desktop/overlay IPC, logs, DHT records or storage.

At most four media sessions/hosts coexist per process; Electron partition sessions are process-lifetime objects, so a bounded pool reuses them after destroying old contents and resetting both permission handlers to deny. These local code-only media pages do not write application storage or keep recordings. Four in-flight commands maximum and a default 12-second host startup/command deadline (configurable up to 15 seconds). Failure, invalid reply, deadline, owner close, renderer loss or navigation destroys the window, rejects pending work, removes IPC listeners and releases the session slot. Future call integration must synchronously close this owner on consent withdrawal/block/hangup/disconnect.

The host fixture found and fixed a real AudioPeer answerer defect: adding a new transceiver before applying the remote offer left the answerer's local track on an unnegotiated transceiver. The answer path now applies the offer first, attaches its local track to the offered audio transceiver and sets sendrecv/Opus preferences. Native tests now require decoded audio in both directions, rather than inferring bidirectional audio from connected transports.
