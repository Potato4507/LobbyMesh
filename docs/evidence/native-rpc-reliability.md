# Native RPC setup reliability — 2026-10-28

/goal: diagnose and mitigate the previously unexplained native replication/lookup intermittency without replaying possibly dispatched application requests.

/steps: baseline typecheck/lint and two native process tests passed at 4be2e74. Added local bounded diagnostic snapshots (32 recent attempts, 16 failures retained separately, saturated aggregate counters), operation/outcome/phase enums and queue/transaction durations only. No peer IDs, transport keys, addresses, payloads, signatures, wall timestamps or raw error messages. Diagnostic observers cannot affect authentication/dispatch. Snapshots copy all retained state; canceled queued tasks remain quota occupants until drained and are recorded as canceled before connect.

The strengthened runtime test performs eight signed PUTs and eight reverse lookups concurrently over two real Windows processes and a local HyperDHT bootstrap. Before mitigation it failed: one B-side FIND_VALUE timed out in hello at 1513.94ms with only 5.02ms queue delay. Following requests then waited roughly 1.52s. All A-side attempts succeeded. This reproduces a pre-application-request setup stall, not proof of its underlying HyperDHT/UDP cause. Installed pinned source was inspected; no node_modules edits, dependency changes, cryptographic changes or increased deadlines.

App-ID-pinned targets now get at most one additional attempt only for RPC_TIMEOUT/RPC_CLOSED while still in hello/proof, before application request transmission. Keep the same request timeout and existing overall/caller AbortSignal. Back off 25–74ms; recheck block and cancellation before opening another stream. Identity/protocol rejection, remote application error and any failure after request transmission never qualify. Existing introduction retries remain separately bounded. Liveness counts one logical final failure, not both physical setup attempts. Every failed setup attempt remains visible even if its retry succeeds. Retry backoff is included in the subsequent attempt duration; queue wait is recorded only on its first attempt. Persistent connection reuse and upstream root-cause resolution remain unfinished.

/proof: Windows Node 24.22.1 / pnpm 11.25.0 / Electron 45.1.0. Focused native/diagnostic/routing suite 11/11 passed; native burst retained one hello timeout while recovering all eight PUTs/eight reverse lookups within original lookup limits. Full suite 93/93, typecheck, lint (98 files), build and native desktop smoke passed. Six new cases cover bounded retention/copy/redaction, phase isolation, queue cancellation, one pre-dispatch retry/single handler execution, finite retries/new block, and no retry on identity mismatch/remote rejection/post-dispatch timeout. Existing signatures/replay/expiry tests retained. A newly canceled queued call previously hit the running assertion first on teardown; abort now takes precedence so its actual outcome is correctly canceled.

Not established: unlimited congestion recovery, cross-NAT, prolonged native churn, universal internet operation, real Roblox or audio acceptance. The new burst is a small local regression, not a benchmark or proof that all historical replication failures share this cause. Default test suite does not contact public bootstrap. Diagnostics are developer/local API only, not a public service or new wire schema.
