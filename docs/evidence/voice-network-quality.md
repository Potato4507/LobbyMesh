# Voice network quality — 2026-10-28

/goal: expose bounded local measurements of an active voice path without confusing network measurements with physical audio latency or retaining endpoint data.

/steps: AudioPeer reads native RTCStatsReport in the dedicated media frame. It emits only roundTripMs, jitterMs and packetsLost, each numeric or null. RTT uses exactly one transport-selected, succeeded candidate pair; it does not guess from arbitrary candidate pairs. Jitter and cumulative loss require one inbound audio RTP record. Missing, ambiguous, non-finite, negative or out-of-bound values become unknown; reported zero remains valid. Time measurements are bounded0–60000ms and packet count must be a nonnegative safe integer. Parsing is capped128 entries; source IDs, candidate addresses, ports and raw reports never cross media IPC or enter retained state. No recording, VAD or speech detection is introduced.

The new quality media operation is read-only and exact-field validated. Main samples only connected owned media, at most once per1000ms with one request in flight. Results taking over500ms are discarded; cached measurements expire after2500ms. Call ownership, cancellation and media-phase epoch checks prevent a late result from repopulating another call or a recovered connection. Stats errors become unknown without ending a healthy call. An unresponsive or invalid media host still follows existing host integrity/timeout teardown; this does not weaken those checks. Permission checks remain authoritative. There is no new remote signaling operation or renderer endpoint input.

Contention refinement: browser stats waiting has its own500ms bound. A timed-out, non-abortable native getStats job retains its one native-job slot until it actually settles, preventing repeated diagnostic jobs from accumulating. Main/renderer reserve one optional quality-command slot independently of the existing four ordinary command slots; optional work skips as unavailable when ordinary capacity is full. A native test issues one quality plus all four ordinary commands concurrently without ending the call. Another injects a stalled getStats, verifies the deadline/no second native job/call stays connected, then releases it and verifies sampling recovers. Regular command quotas and host integrity rejection remain enforced.

Conversations shows Network RTT, Inbound jitter and Lost packets during a connected call, with explicit Unavailable text for null. The explanation identifies loss as cumulative and RTT as a network-path measure, not mouth-to-ear latency. No new sampling timer exists in the renderer; main uses its existing call poll. Capture/PTT/volume/consent behavior is unchanged.
